## Oddities (not failures)

1. **Vite's local servers add cross-site headers on `/api/visits`.** Under `npm run dev` and under `vite preview` (the built app run locally), `OPTIONS /api/visits` answers 204 with `Access-Control-Allow-Methods`, and any `/api/visits` answer echoes `Access-Control-Allow-Origin` for a `http://localhost:*` origin (for example `http://localhost:3000`). Outside origins get no such header. This is Vite's own default, not the Worker: the Worker's unit tests give OPTIONS 405 and never send the header, and on the preview Access stops OPTIONS (400) before the Worker. Job 1's evaluation said this happens "in `npm run dev` only"; it also happens under `vite preview`. Reproduce: `npm run build`, `npx vite preview --port 4173`, then `curl -i -X OPTIONS -H "origin: http://localhost:3000" http://localhost:4173/api/visits`. Worth a `server.cors`/`preview.cors: false` line in a later job.
2. **A reload before the first request leaves WebKit sends no POST for that interrupted load.** Under `npm run dev` in WebKit, reloading the instant "Saving your visit." appeared gave 1 POST for 2 loads; with 300 ms more, both loads sent one (the first was then cancelled by the browser). The interrupted load never finished, so this is not a broken count. Trace: `2-reload-mid-save-trace-dev.txt`.
3. **Keyboard focus ring on the status line.** After "Try again" by keyboard, Chromium draws its default focus box around the status sentence (`3-retry-saved-built-chromium.png`). This is the intended focus move with browser defaults; job 4 should style it.
4. **`pg_graphql` is not installed on the test project** (`5-7-12-db-catalog.txt`), yet `/api/health` reports `database: reachable`. The health check accepts any JSON 200 from `/graphql/v1`, so it may be weaker than its name says. Out of scope here (the spec says leave it); worth checking in job 3.
5. **Port 5173 was already taken** on this computer by another server (an older page calling `/api/health`). Someone following `build.md` ("open http://localhost:5173") could see the wrong app. I used port 5199.
6. **The current `build.md` points to git history** (commit 52307b7) for the list of changed job 1 test lines instead of repeating it. The list there is complete and matches the diff.
7. **Slow network under `npm run dev`** with 2 s latency did not finish loading in 60 s (dev serves many separate module files). The built app on the same throttling saved the visit in about 11 s with one POST.
8. **Row volume.** The test project already holds about 380 visits from check runs, preview runs and this evaluation. Each full check run adds roughly 100. Harmless, but job 3 should decide whether to drop `visits`.
9. **Open owner item from review:** the test database password is still the one a reviewer's log exposed (`SUPABASE_TEST_DB_URL` last updated 16:47 today). Rotation was deferred by the owner.

## Must fix before merge

1. **`npm run check:code` fails on a Windows checkout.** `.gitattributes` gives every code folder `text eol=lf` except the new `review-site/`. On a Windows clone (core.autocrlf true) the five files in `review-site/` check out with CRLF line endings and Prettier flags all five, so the format check fails. That will happen in the owner's main folder after the merge and in every future job worktree. The builder's own worktree passed only because its files were written directly with LF. GitHub's Linux check stays green, which is why the pull request shows nothing.
   Steps: `git clone --branch factory/13-review-site <repo> x && cd x && npm ci && npm run check:code` on Windows. Result: `[warn] review-site/dialogues.json`, `handler.test.ts`, `handler.ts`, `worker.ts`, `wrangler.jsonc`, exit 1. `git ls-files --eol review-site` shows `i/lf w/crlf attr/`. Evidence: `eval-odd-crlf-format-check.txt`, `eval-odd-check-code-windows-clone.txt`. Fix: one line, `review-site/** text eol=lf`, in `.gitattributes`.
2. **One Worker test passes for the wrong reason (the 3-data-model lesson).** "[site 6] a team domain that is not a cloudflareaccess.com address is refused, so keys are never fetched elsewhere" stays green when the team domain shape check is removed. The test's stand in key source throws (`expect(team).toBe(TEAM)`) inside the Worker's try block, and that throw produces the 403. The test never asserts that the key source was not called. In production, without the shape check, a team domain variable set to an attacker's site would make the Worker download that site's keys and accept its tokens; the deploy step's own shape check is then the only guard. The same holds for "when either setting is missing": removing the whole settings check leaves every test green, because the token library and the key lookup refuse instead. The refusals happen today, so no statement fails, but the tests do not prove the protection they name.
   Steps: in a scratch copy, change `if (!TEAM_DOMAIN.test(teamDomain) || !AUD_TAG.test(aud)) return false` to `if (!AUD_TAG.test(aud)) return false`, or delete the line, then run `npx vitest run review-site`. Result: all pass. Evidence: `eval-breaks-tests-go-red.txt` (last four lines). Fix: make the key source a spy and assert it was never called for a bad or missing team domain or AUD.

## Odd but not failures

The threat model says the system refuses deploys from branches "even if asked nicely". A GitHub environment for the deploy job, limited to the main branch, would enforce that on GitHub's side. Worth a look by the security reviewer; the repository uses no environments today.

## Findings

No must fix findings.

1. **Should fix.** `lefthook.yml:15` (top level, before `pre-commit:`). Risk: when lefthook cannot be found, the generated `.git/hooks/pre-commit` prints "Can't find lefthook in PATH" and exits 0, so the commit goes through with no secret scan. This is what happens on main after `.worktrees/4-tooling` is removed and before someone runs `npm ci` in the main checkout (build.md proved it, 0.8 s, exit 0). Manager commits straight to main are not scanned on GitHub (the CI secret scan covers pull request commits only), so for those commits the local hook is the only secret scan. Fix: add `assert_lefthook_installed: true` at the top of `lefthook.yml` (lefthook 2.2.2 supports it; the hook template then exits 1 with the same message), run `npm ci` again so the hook is regenerated, and add a line to the statement 13 evidence showing a refused commit with lefthook missing. This makes "a missing tool fails safely" cover lefthook too.

2. **Should fix.** `lefthook.yml:15` and `tests/claude-settings.test.ts`. Risk: lefthook 2.2.2 has an `ai:` setting that writes `.claude/settings.json` (Claude Code hooks, which run any command in every session) during `lefthook install`, so on every `npm ci`. It has a `remotes:` and `extends:` setting that pulls more hook config from another git repository or file at commit time. None are used today, but if one is added, the settings file the owner controls would be rewritten on disk before any test sees it, and `tests/claude-settings.test.ts` only checks the committed file. Fix: add a `[tooling 16]` test that reads `lefthook.yml` and fails if it has an `ai`, `remotes` or `extends` key. Optionally also check that `.claude/settings.json` is unchanged after `npm ci` in the statement 8 evidence.

3. **Note.** `lefthook.yml:55` (`gitleaks ... --redact --verbose`). With `--verbose`, gitleaks prints the "Finding" line with the rest of the source line, and only the detected part is redacted (evidence `10-local-refused-made-up-key.txt` shows `...onst githubToken = 'REDACTED`). A second secret on the same line that no rule detects would be printed into the agent's transcript. Low chance. If you want to close it, print only file, line and rule, as the stop check does (`--report-format json --report-path -`, then keep those three fields).

4. **Note.** `scripts/hooks/stop-checks.ts:264-267` and `:297-306`, `.claude/settings.json` `"timeout": 120`. A usage error or a crash exits 1, and a timeout is also non-blocking, so in each case Claude Code lets the builder stop unchecked. The commit check and GitHub still catch the problem, so the risk is low. If you want it to fail closed, return 2 from the crash handler with the same one-line message.

5. **Note.** `scripts/hooks/stop-checks.ts:109-111` and `:178-203`. The stop check runs from the main checkout, but for each worktree it starts that worktree's own `node_modules` copies of tsc, ESLint and Prettier, and ESLint loads that worktree's `eslint.config.js`. On Windows, Node looks in the working folder before PATH, so a `gitleaks.exe` in a worktree's root would run instead of the real one. All of this runs as a hook, outside Claude Code's permission prompts. The builder can already run any command through Bash and every `npm ci` runs install scripts, so this gives a builder no new power today. It becomes a real gap only if builders are later restricted.

6. **Note.** Shared `.git/hooks/pre-commit`. It is generated by whichever checkout ran `npm ci` last, and today it starts `C:/Users/fumna/dev/puhuscribe-v3/.worktrees/4-tooling/node_modules/lefthook-windows-x64/bin/lefthook.exe`. A branch that changes the lefthook version in its lockfile changes the binary that runs on the owner's and the manager's commits on main before that branch is reviewed. The config each commit uses is still the committing checkout's own `lefthook.yml`. As with note 5, `npm ci` on a branch already runs that branch's install scripts on this computer, so the risk does not grow. Running `npm ci` in main after each merge (already a manager to-do) puts the hook back on main's reviewed packages.

## Looked at closely, passes

- **lefthook dependency.** `package.json` pins `"lefthook": "2.2.2"` exactly (MIT). The lockfile pins the main package and the 11 per-platform packages with sha512 integrity from registry.npmjs.org. `postinstall.js` downloads nothing: it runs the prebuilt binary from the matching optional npm package (`lefthook-windows-x64`) with `install`, and returns at once when `CI` is set and `LEFTHOOK` is not. The apply job, the only one holding the database password, runs no `npm ci`. I found no telemetry endpoint in the binary's strings. The AI integration is the `ai:` config key (see finding 2). `npm audit` is clean (build.md, CI).
- **`lefthook uninstall` rewrote `.claude/settings.json`.** The builder restored it from git. The main checkout's copy is unchanged (clean git status), and `docs/conventions.md:135` tells agents not to run uninstall. `lefthook install` with today's `lefthook.yml` leaves the file alone (no `ai:` key).
- **`.claude/settings.json`.** Exactly the spec's option B JSON, pinned by `tests/claude-settings.test.ts` with `toStrictEqual`. The progress log is the only `Stop` hook. `SubagentStop` matches only `factory-builder`. The command runs main's own `scripts/hooks/stop-checks.ts` through `node`, with no shell string built from input. No other `.claude/` file changed.
- **The stop check and secrets.** It finds files only through git, so git-ignored files such as `.env.local` and `.dev.vars*` are never listed. The name filter drops any `.env*` file as a second guard (`stop-checks.ts:44-52`). It prints only check, file, line and rule: tsc and ESLint messages, Prettier parse errors that quote code, and gitleaks matches are all reduced to positions. gitleaks runs with `--redact` and its report goes to stdout, never to a file. The tests build the made-up key at run time, check that neither the whole value nor a slice is printed, and check that a key in an untracked `.env.local` produces no output. The mutation evidence shows that removing `--redact` turns the test red. That secret test is skipped on GitHub because gitleaks is not installed there. It ran locally.
- **The commit check's gitleaks run.** `gitleaks git --pre-commit --staged --redact` scans only the staged diff, writes no report file, and the commit is refused on exit 1. `commit-tool.ts` uses `spawnSync` without a shell and passes the tool's exit code through. A missing gitleaks or ruff refuses the commit with a fixed install line (`winget install --id Gitleaks.Gitleaks -e`; `pip install --user -r scripts/requirements-dev.txt`, which pins `ruff==0.17.1` and `pip-audit==2.10.1`). Both installs are free and need no administrator rights or secrets.
- **Concurrency (`checks.yml:30-32`, `:195-197`).** A push to main or a manual run gets its own group (`run_id`) with no cancelling. A pull request still cancels its own older run. The apply job's `apply-test-db` group, with no `cancel-in-progress`, lets only one apply run at a time. `queue: max` keeps up to 100 waiting, so none is dropped in practice. Tests pin both and check that no other job has a concurrency block. **Owner should know:** applies run in the order their runs' database jobs finish, which may differ from the order of the pushes. If an older run's apply comes second, `supabase db push` from the older commit finds a remote migration it does not have and fails red. Nothing is lost, but the run needs a rerun. This proof happens only at merge, as the spec says.
- **AGENTS.md and docs/conventions.md** teach no unsafe habit. They repeat "never read, search or print `.env*`, use `git grep`", forbid `--no-verify` and `LEFTHOOK=0`, and say not to run `lefthook uninstall`. The "Result: blocked:" exit from the stop check is by design, and the builder must state a reason. `tests/agents-md.test.ts` only checks that paths exist and reads no `.env*` file.
- **Evidence files.** The made-up key appears only redacted or as a description. `git grep` for connection strings, JWTs, `sk-`/`ghp_` tokens and `NAME=` secret lines over the 18 new evidence files found nothing, and `gitleaks dir factory/jobs/4-tooling/evidence --redact` found no leaks.

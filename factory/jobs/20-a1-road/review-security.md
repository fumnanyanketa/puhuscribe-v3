## Findings

### Should fix

1. **The owner's approval fingerprint does not cover the audio, the word links or the speakers.**
   File and line: `scripts/generate/road_publish.py:56` to `77` (`road_fingerprint`), and `road_preconditions` at `:153` to `:176`.
   Risk: the threat model names "swap an audio file" as a way to put wrong Finnish in front of learners and lists the approval fingerprint as the defence, but the fingerprint hashes only the three line texts and the form texts, so a clip replaced after approval (with its `sha256` rewritten in `draft.json`, which the publisher only compares with the file) still publishes under the owner's old approval.
   The same holds for which word links to which form (`kirja_tokens`/`puhe_tokens`) and for the speaker, which the publish migration reads from the draft.
   Fix: add each clip's `sha256` per line and register, the speaker of each line, and the token to form links to the fingerprint input. Re-voicing a line then voids that dialogue's approval, which is the right result. The "swap an audio file" row in the threat model should then say so. If the owner prefers to keep statement 20's narrower definition, record in `summary.md` that audio is not bound by the approval.
   This needs a spec change to statement 20, so it is not marked must fix. The exposure needs a committed change plus an owner approved merge.

2. **The Azure character guard counts only what is committed.**
   File and line: `scripts/generate/providers/voice.py:113` to `:123` (`month_characters`), used at `scripts/generate/road_import.py:917`.
   Risk: the workflow runs on a fresh checkout and reads `content/logs/ai-calls.jsonl` from git, so characters from a run whose artifact was not committed yet are forgotten, and the "450,000 stop" can be passed by repeated runs before anyone commits the log.
   Fix: say in `docs/content-pipeline.md` that the manager commits the log after every voice run and before the next one. The free tier (F0) itself refuses calls past 500,000 and `voice.py` refuses any tier but F0, so the money risk stays zero. This is a process note, not a bill risk.

4. **The judge limit can overshoot by one call.** `providers/ai.py:64` checks the run cost before each dialogue, so the last call can pass $2 by about a cent. Every call is logged with its cost (`ai.py:88`) and the key never appears in the new code. Briefs go to Anthropic's service outside the EU, which the spec already records (game content only, no learner data).

6. **No injection through the override and fix files.** `road_markdown.py:55` refuses a pipe or line break in a fixed cell, `road_data.py` validates every override row (known tag, source, reason), the publisher escapes every value with `sql_text` and refuses code block text (`unsafe_texts`), and the review page writes text with `el(...)` as text (`review_page.py:235`, `:237`). A reviewer fix is re-imported, goes through `check_draft` and stops on any failure or missing word card text before any audio or SQL is written (`pipeline.py:432` to `:446`).
7. **A visitor can call the function directly and repeatedly.** `supabase/migrations/20261101120200_road_for_visitors.sql` is open to anyone with the publishable key and scans the approved tokens (about 14,000 rows when the road is live) on each call, and the Worker answers `no-store`. Not a data risk. If abuse appears, add a Cloudflare rate limit on `/api/road` or a short shared cache on the visitor answer only (never on the learner answer).
8. **A stale sign in cookie stays after an ended session.** `worker/api.ts` (road route, "A fault stays a fault" block): the visitor answer drops the cookie clearing by design (statement 29 says no Set-Cookie), so such a browser makes one Auth call per `/api/road` request until another route clears it. 9. **Names of unpublished stops are now readable by anyone**, not just signed in learners. Stop names and "I can" sentences are already in the public repository, so nothing new leaks. Statement 29's threat note covers it.
10. **The approval file is only a process lock.** `content/approvals/part-<n>.json` can be written by anyone who can commit, and `read_approval` cannot tell the owner's line from a made up one. ## What was checked and passes

- **Migration `20261101120000_a1_road.sql`.** `road_parts` and `road_stops` revoke all from anon, authenticated and service_role, grant select to authenticated only, have row level security and one read policy each, and hold English only. `road()` and `stop_review_forms()` are `security invoker`, `set search_path = ''`, `stable`, all objects schema qualified, execute revoked from public, anon, authenticated and service_role and granted to authenticated only. They filter on `auth.uid()` for sessions, review logs and cards, and the other tables go through the learner read rules, so another learner's progress cannot be counted. Neither returns a Finnish word or any id of another learner (`stop_review_forms` returns the caller's own form ids only). The two new `forms` columns are covered by the freeze trigger, which compares the whole row (`20261020090000_content_model.sql:185`, `:193`), and by the stricter `forms_approval_complete`. The guard refuses to run when approved forms exist.
- **Migration `20261101120200_road_for_visitors.sql`.** `security definer`, empty search path, `stable`, no `auth.uid()` and no learner table in the body, only approved dialogues, lines, forms and units are counted, the three progress columns are the literal 0, execute is revoked from public, anon, authenticated and service_role and granted to `anon` only. The pgTAP checks (`a1_road.test.sql:524` to `:573`) prove each of these, including that learners with finished sessions give a visitor 0, and the build notes show each break going red alone.
- **`GET /api/road` (`worker/api.ts`, `worker/road.ts`).** With no cookie it makes no Auth call, reads only `road_for_visitors` with the publishable key through `blankContext` (a request with no cookies), never calls the learner function and sets no cookie. An invalid or ended session becomes a visitor answer without the cookie changes. An Auth outage stays a 503. The Worker also zeroes the three progress columns itself and refuses any row that is not exactly the 14 columns. A fault answers 503 with `{error: 'not_available'}` and no detail. All answers are `cache-control: no-store`, so a learner's answer cannot be cached for a visitor. POST is refused.
- **Paging (`worker/paging.ts`, `learner-db.ts`, `patterns.ts`).** Reads are still made with the learner's token, so row level security still applies. Paging only adds `order` and `range`. Chunked `in` lists keep the filters the old reads had.
- **Voices and AI.** No call to voice or AI services from the browser. Voice stays behind `providers/voice.py` (EU region list, F0 only, text only sent, 20 requests a minute, retry on 429 and 5xx, resume by hash). The AI judge module is the existing one. Nothing in the road sends learner data or recordings anywhere.
- **Publish path.** `publish_part` checks every dialogue of the part before it writes anything, `road_preconditions` refuses on a missing or malformed approval file, an unlisted dialogue, a changed fingerprint, a judge state that differs from the one approved, a failing check, missing word card texts, a fake or missing clip and a clip that differs from its recorded hash. Each `approval_ref` carries the approval file path and the dialogue and item, so each is new. The unit is approved only inside the last dialogue's migration. The fix migration puts the dialogue and changed lines back to draft before replacing words, then approves them with new references, so approval is cleared and the old reference stays in `private.approval_history`.
- **Learner data, retention and consent.** No new learner table, no recordings, so the existing export and deletion paths cover everything (`road()` reads existing session and review rows only).
- **Dependencies.** No change to `package.json`, lock files or `scripts/requirements-pipeline.txt`.

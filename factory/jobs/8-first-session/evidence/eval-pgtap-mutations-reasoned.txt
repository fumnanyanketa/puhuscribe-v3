The rule (policy "learners add events for their own finished sessions"):
  user_id = auth.uid()
  and exists (session s: s.id = session_id, s.user_id = auth.uid(),
              s.step_reached >= 'understand', s.ended_at is not null)

State when the insert tests run (A acting): A001 understand, NOT ended; A002 hear, not ended;
A003 no step; A004 (dialogue 2) understand, not ended; B001 understand, ended by B, B has an event.

P1. Remove "user_id = auth.uid()".
    Test "[session 17] A cannot add an event carrying B's id" inserts (user_id B, session A001).
    A001 is not ended, so the exists part is false and the insert is still refused with the same
    42501 message. The test stays green: it cannot see this break.
    Real effect of the break: once A has finished a session, A could add an event that carries B's
    id (any learner who has no event yet). This is the "forged event" case.
    Verdict: protection present in code, NOT proven by its test.

P2. Remove "s.step_reached >= 'understand'".
    Test "A cannot add an event for a session at step hear" uses A002, which is also not ended, so
    the ended_at part still refuses. The test stays green. No other test isolates the step part.

    part is not redundant.)
    Verdict: NOT proven in isolation (the builder's red scratch run removed all the session
    conditions at once, which is why it went red).

P3. Remove "s.ended_at is not null".
    Test "A cannot add an event for a session at understand that has not ended" (A004) is then

    Verdict: proven.
